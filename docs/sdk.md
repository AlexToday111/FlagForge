# Go SDK

`NewClient` starts an owned polling worker, optionally a streaming worker and an analytics worker. Every worker shares cancellation; `Close` cancels and joins them. Snapshot/analytics requests have timeouts; stream handshakes and idle periods have an idle timer. Redirects are rejected so bearer credentials cannot follow a redirect. Custom HTTP clients are copied before redirect configuration is set; use a client without a short whole-response Timeout for SSE.

With `WaitForInitial`, creation waits for synchronization until `InitialTimeout` and returns an error on timeout. Without it, creation returns immediately and applications evaluate bootstrap/defaults while the server is unreachable. `Ready` means a remote configuration was fetched (or an explicit offline bootstrap is installed), not that the server remains reachable. `Status` reports last synchronization, error, revision, dropped events and last notification-to-SDK propagation estimate.

`BootstrapFlags` supplies unversioned defaults of inferred types before the first remote snapshot. `Bootstrap` supplies a complete versioned snapshot, including scope, segments and prerequisites. Scope must match future remote snapshots. Offline mode starts no network worker. To persist across process restarts, the application can own a serialized bootstrap file using `Store.Snapshot`; automatic disk persistence is not provided.

Atomic snapshot replacement copies and validates all data once per update. Readers incur no mutex contention and see a coherent graph. Cost is temporary old+new snapshot memory and copying on updates. An RWMutex map would use less copy memory for small changes but make frequent readers contend with update writers. The public Store returns owned snapshot copies; evaluations do not expose mutable configuration maps. Duplicate/older revisions are ignored with CAS, including concurrent poll/stream responses.

Analytics is disabled unless configured. A bounded channel uses nonblocking writes; full buffers drop events and increment a status counter. One worker batches up to 100 events, flushes every 5 seconds by default, and uses bounded request timeouts. Failed batches are dropped; counts are best effort and not billing-grade. Close cancels requests and counts queued items as dropped, avoiding shutdown stalls. Evaluation context/subject data never enters analytics.
